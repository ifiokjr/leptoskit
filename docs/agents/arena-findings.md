# What the arena found in leptoskit

The arena ([`benchmarks/arena`](../../benchmarks/arena/README.md)) runs the same self-driving app in leptoskit, React Native, Lynx, and Flutter. Building the leptoskit app was itself an audit: every scenario that needed something leptoskit lacks had to be marked unsupported or bent around the gap. This page lists those gaps, and the first numbers that show where leptoskit is slow. It is the work list for making leptoskit win.

The numbers here are first readings from the iOS simulator, a loaded Android emulator, and macOS while the machine was busy. They show the shape of each problem, not its size on a phone. The committed results in `benchmarks/results/arena-*.json` replace them as they are measured on a quiet machine and physical devices.

## Missing capabilities

Each of these blocked or bent a scenario. Each fix is a public API, so it needs a design note before code.

| Gap                                                                                 | What it blocks                                                                                                                                                                                                                                                                          | Where it would go                                                                                                                                                |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No frame clock for guests                                                           | `ticker` and any animation driven by app code. The arena app ships its own native plugin (`plugins/arena_bridge`) whose `next_frame` call waits for `CADisplayLink` or `Choreographer`. Every frame is therefore an asynchronous plugin round trip, and no app author would write that. | A guest import in the rendering ABI (`crates/leptoskit_native/src/guest`), backed by each host's display link in `crates/leptoskit_bridge_ffi/{mobile,desktop}`. |
| Scroll views have no programmatic offset                                            | `autoscroll` and `busy` are unsupported. `scrollTo`, animated or not, is the most basic list interaction after rendering one.                                                                                                                                                           | A `ScrollView` handle or prop in `leptoskit_native`, plus the Swift, Kotlin, GTK, and Win32 renderers.                                                           |
| Generated iOS, Android, and macOS apps report no scroll events                      | A guest cannot know where a list is, so it cannot virtualise one or react to scrolling. The backend crates report them; the generated apps' renderers don't.                                                                                                                            | `crates/leptoskit_bridge_ffi/mobile/MobileWidgetRenderer.swift`, `LeptosKitView.kt`, and the desktop renderer.                                                   |
| The guest runs on the UI thread                                                     | Slow app code stalls native scrolling and touch handling. React Native and Lynx run app logic off the UI thread; Flutter merged its threads in 3.29 and pays the same cost. `busy` will show this once scrolling exists.                                                                | `crates/leptoskit_bridge_ffi`: a guest thread that posts committed transactions to the UI thread.                                                                |
| No first-frame time                                                                 | The app cannot report when its first frame was presented relative to process start. Flutter has `firstFrameRasterized`, and Lynx has `fcp`.                                                                                                                                             | A host callback after the first transaction is drawn, exposed to the guest and the logs.                                                                         |
| Plugins written by an app need a separate Rust implementation for Windows and Linux | The arena has no leptoskit numbers on Windows or Linux: its plugin exists in Swift and Kotlin only.                                                                                                                                                                                     | The plugin docs, and possibly a shared Rust implementation path for desktop plugins.                                                                             |
| No GPU surface                                                                      | 3D, and any custom drawing beyond the seven components.                                                                                                                                                                                                                                 | A `Canvas`/`GpuView` component with a host-provided Metal, Vulkan, or Direct3D surface.                                                                          |

## Where it is slow

| Reading                                                                                                       | What it suggests                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mount`, Android emulator: 1,000 cards in 908 ms, every tenth updated in 571 ms, cleared in 68 ms             | Updating 100 labels costs most of what creating 1,000 cards does. Every state change re-runs the whole screen function and diffs the whole tree. Fine-grained updates (leptos signals on native, or keyed memoisation of subtrees) would make it proportional to the change. |
| `ticker`, iOS simulator: 53 frames in 5 s; Android emulator: 12                                               | Each frame is three trips: a plugin call for the frame, then a full re-render, then a JSON transaction. In the same 5 s on the same emulator, the React Native app applied 71 updates, Lynx 178, and Flutter 30.                                                             |
| `echo`, 64 KiB of bytes: about 1.75 ms on macOS and 3.2 ms on Android, against 25 µs and 14 µs for an integer | Bytes are copied more often than the bridge's own microbenchmark, which copies nothing, would suggest: into and out of wasmi's memory, and across the Swift or Kotlin boundary. Each copy needs to be found and removed.                                                     |
| `echo` on Android: integer p99 6.8 ms against a p50 of 14 µs                                                  | Something stalls the reply path now and then: the main-thread executor, garbage collection on the Kotlin side, or the polling interval.                                                                                                                                      |
| Two JSON hops per update                                                                                      | The guest sends JSON props to the Rust host. The host diffs, lays out, and serialises the mutation list as JSON, and Swift or Kotlin decodes it with `JSONDecoder` before touching a widget. A binary transaction format, or a direct FFI call per mutation, removes both.   |

## Smaller findings

- `leptoskit native build android` prints "built; no artifact found to measure". `crates/leptoskit_cli/src/native/size.rs` still looks under the old `hosts/android/…` path, but scaffolds now put the Gradle project in `android/`.
- `leptoskit native build android` needs `JAVA_HOME`. Without it, Gradle fails with "Unable to locate a Java Runtime", where it could fall back to Android Studio's bundled JDK the way the other frameworks' tooling does.
- The guest learns its launch scenario through an asynchronous plugin call, so the first commit is an empty screen and the ready screen is the second. A synchronous launch-arguments import would let the first commit be the real one.
