# What the arena found in leptoskit

The arena ([`benchmarks/arena`](../../benchmarks/arena/README.md)) runs the same self-driving app in leptoskit, React Native, Lynx, and Flutter. Building the leptoskit app was itself an audit: every scenario that needed something leptoskit lacks had to be marked unsupported or bent around the gap. This page lists those gaps, and the first numbers that show where leptoskit is slow. It is the work list for making leptoskit win.

The numbers here come from `benchmarks/results/arena-*.json`: a Seeker phone (Android 16, a 120 Hz display) for frames and latency, and release builds on a Mac for sizes. Where an early reading came only from a simulator or emulator, it says so.

## Missing capabilities

Each of these blocked or bent a scenario. Each fix is a public API, so it needs a design note before code.

| Gap                                                                                                     | What it blocks                                                                                                                                                                                                                                                          | Where it would go                                                                                 |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| ~~No frame clock for guests~~ addressed by `leptoskit::guest::next_frame`                               | `ticker` and any animation driven by app code. The host's display link now resolves a reserved bridge plugin and lets the guest render inside the same callback. On macOS the ticker went from 88 to 110 updates in 5 s; the rest of the gap is render cost, below.     | `crates/leptoskit_bridge/src/frame.rs`, `lk_app_frame` in `crates/leptoskit_bridge_ffi`.          |
| ~~Scroll views have no programmatic offset~~ addressed by `Element::scroll_offset`                      | `autoscroll` and `busy` now run. The web and the generated Swift and Kotlin renderers apply it; the AppKit, UIKit, Android, GTK, and Win32 backend crates don't yet.                                                                                                    | The backend crates' scroll views.                                                                 |
| ~~Generated iOS, Android, and macOS apps report no scroll events~~ addressed                            | The generated renderers report each move, and report where a scroll set from code settled once the transaction is applied. A scroll view's direct content now keeps its native view, so its full size, such as a virtual list's total height, sets the scrollable area. | `ScrollTracker.swift`, `NativeWidgetRenderer.kt`, and `flatten.rs`.                               |
| ~~The guest runs on the UI thread~~ addressed on iOS and Android by the [guest thread](guest-thread.md) | The generated iOS and Android apps now run the guest, layout, and rendering on a thread of their own, so slow app code no longer stalls native scrolling and touch handling there; the macOS app keeps the main-thread runtime for its AppKit plugins.                  | `crates/leptoskit_bridge_ffi`: a guest thread that posts committed transactions to the UI thread. |

| No GPU surface                                                                                          | 3D, and any custom drawing beyond the seven components.                                                                                                                                                                                                                 | A `Canvas`/`GpuView` component with a host-provided Metal, Vulkan, or Direct3D surface.           |

## Where it is slow

| Reading                                                                                                                                                                                   | What it suggests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ~~`mount` on the Seeker (Android 16, 120 Hz): 1,000 cards reach the screen in 1,438 ms and an update of every tenth in 398 ms~~ addressed by signal bindings                              | Every state change used to re-run the whole screen function and diff the whole tree, so updating 100 labels cost a quarter of creating 1,000 cards and eight times what Flutter paid. The arena now holds its state in signals and binds the values that change in place, so the update rewrites 100 labels and the beacon instead of rebuilding 3,000 elements: on the Seeker, 1,000 cards reach the screen in 103 ms and an update of every tenth in 17 ms, against Flutter's 250 ms and 48 ms, Lynx's 443 and 60, and React Native's 755 and 62. Clearing 1,000 cards takes 17 ms, against Flutter's 28. Each app times its own state change to its earliest after-frame hook and reports the hook it used; leptoskit's waits for the display frame after its widgets change, where Flutter's ends before rasterization. |
| ~~`ticker` on the Seeker: 5.5 presented frames per second~~ addressed by the frame clock and the render work below                                                                        | Each frame used to be three trips: a plugin call for the frame, then a full re-render, then a JSON transaction. The Seeker now presents 74 frames per second with 0.9 ms of hitch per second, against Lynx's 58 fps and 130 ms/s, React Native's 29 fps and 478 ms/s, and Flutter's 27 fps and 564 ms/s.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `echo` on the Seeker: 64 KiB of bytes in 2.18 ms, against Flutter's 0.19 ms and Lynx's 0.39 ms; the integer round trip is fast (73 µs, against Flutter's 70 µs and React Native's 106 µs) | Bytes are copied more often than the bridge's own microbenchmark, which copies nothing, would suggest: into and out of wasmi's memory, and across the Kotlin boundary. Each copy needs to be found and removed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Two JSON hops per update                                                                                                                                                                  | The guest sends JSON props to the Rust host. The host diffs, lays out, and serialises the mutation list as JSON, and Swift or Kotlin decodes it with `JSONDecoder` before touching a widget. A binary transaction format, or a direct FFI call per mutation, removes both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Size tiers: about 10 KB per extra screen on macOS and the web, against about 2 KB for React Native, Lynx, and Flutter                                                                     | leptoskit has the smallest fixed cost on every native platform (iOS 5.0 MB against 13.6–20.3 MB; Android 5.8 MB against 12.0–18.1 MB; macOS 3.3 MB against Flutter's 36.9 MB), but each screen of app code compiles to more Wasm than the others' bytecode or AOT code. On iOS and Android the guest ships gzipped inside the code push baseline, which hides most of it (1.5 KB a screen). Builder-style element construction and per-screen monomorphisation are the first places to look.                                                                                                                                                                                                                                                                                                                                |

## Found while profiling the fixes

| Reading                                                                                                                     | What it suggests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ticker` on macOS with the frame clock: per frame, about 10 ms in `lk_app_frame` and 11 ms in Core Animation's commit       | Half of `lk_app_frame` was `leptoskit_yoga` laying out the whole tree. Relayout boundaries (a changed label inside a fixed cell lays out only that cell) took the native commit probe from 1.56 to 0.55 ms, and yoga no longer shows in the frame's profile. What remains is the guest's interpreted render (about 7 ms) and AppKit committing 300 `NSTextField`s (about 17 ms). Each label field is a control, a cell, and a private drawing subview. A plain view drawing the same attributed string (`TextLabel`) took the ticker from about 100 to about 150 updates in 5 s; it inks the same pixels but misses AppKit's private font dilation, so edges are a shade lighter, which was judged worth the speed. The guest's render was then the larger half. Counting its interpreter instructions (wasmi fuel) put a ticker frame at 16.4 million: `.class()` formatting its string cost more than the cached parse, the class cache hashed with SipHash, and the tree lived in a `BTreeMap` of 850-byte nodes. Fixing those took a frame to 10.1 million instructions, updating every tenth card from 51 to 32 ms, and the ticker to about 170 updates in 5 s. |
| `mount` on macOS after the render fixes: creating 1,000 cards takes 490 ms of wall time, but the main thread is mostly idle | The rest is the system compositor drawing about 3,000 native views. View flattening now gives layout-only containers no view at all, which took creation to 412 ms; the remaining views are the 2,000 labels themselves. Drawn labels then took creation from about 430 to 235 ms, and clearing from 132 to 74 ms.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| A `mount` step in leptoskit now lands in one or two display frames                                                          | The beacon recording cannot resolve it: Android's recorder often encodes neither the running frame nor the done frame, and when the done frame is the one it drops, the window spans two steps. The benchmarks chapter now ranks `mount` by each app's own after-frame hook; `create_to_pixel_ms`, `update_to_pixel_ms`, and `clear_to_pixel_ms` stay in the results file wherever the frames are there. Raising the recorder's settle time from one second to three also fixed the scenarios that end on the done beacon, where `ticker` lost that frame on every launch.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Smaller findings

- `leptoskit native build android` prints "built; no artifact found to measure". `crates/leptoskit_cli/src/native/size.rs` still looks under the old `hosts/android/…` path, but scaffolds now put the Gradle project in `android/`.
- `leptoskit native build android` needs `JAVA_HOME`. Without it, Gradle fails with "Unable to locate a Java Runtime", where it could fall back to Android Studio's bundled JDK the way the other frameworks' tooling does.
- The guest learns its launch scenario through an asynchronous plugin call, so the first commit is an empty screen and the ready screen is the second. A synchronous launch-arguments import would let the first commit be the real one.
