# iOS

On iOS, your screens are drawn with UIKit: a `Button` is a `UIButton`, a `TextInput` a `UITextField`, a `ScrollView` a `UIScrollView`. The app that `leptoskit new` generates is a small UIKit app that runs your screens as WebAssembly, so it can also replace them over the air with [code push](../guide/05-code-push.md).

## What you need

- A Mac with Xcode and an installed iOS simulator runtime.
- The Rust targets for the simulator and for devices:

```bash
rustup target add aarch64-apple-ios-sim aarch64-apple-ios wasm32-unknown-unknown
```

On an Intel Mac, the simulator target is `x86_64-apple-ios`.

## Run it in the simulator

```bash
leptoskit native build ios-simulator
open .leptoskit/ios/Host.xcodeproj
```

The first command compiles your app to WebAssembly, compiles the UIKit host, and generates an Xcode project. In Xcode, pick a simulator and press **Run**. Simulator builds are signed ad hoc, so you don't need a development certificate.

The Xcode project is regenerated by every build. Make your changes in the `ios/` folder instead: `App.swift` starts the app, `Info.plist` holds its name, version, and permission strings, and `Cargo.toml` lists native Rust dependencies such as [runtime plugins](plugins.md).

## Run it on a device

```bash
leptoskit build --platform ios
```

This builds for `aarch64-apple-ios`. Device builds are not signed: open `.leptoskit/ios/Host.xcodeproj`, choose your development team under **Signing & Capabilities**, and run it on your device. Do the same for App Store distribution.

## Test it

Each project includes a UI test, `ios/AppUITests.swift`, that taps **Add one** and waits for **Count: 1**. Update it when you change the home screen, then run it on a simulator:

```bash
xcodebuild -project .leptoskit/ios/Host.xcodeproj -scheme App \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- test
```

## How it differs from macOS

- The generated app draws eight components: `View`, `Text`, `Button`, `Pressable`, `TextInput`, `ScrollView`, `Image`, and `Vector`. Others, such as `Switch` or `PasswordInput`, stop it with an "unsupported widget" error. The `leptoskit_uikit` backend crate draws every component, including a `UISwitch`, `UISlider`, and `UIProgressView`, when you host screens with `UIKitHost` in your own app; see [generated apps and backend crates](readme.md#generated-apps-and-backend-crates).
- In the backend crate, iOS has no native checkbox or radio button, so `Checkbox` and `Radio` are drawn with `UIButton`.
- VoiceOver gets fewer roles than macOS's accessibility API, and no expanded or collapsed state.
- A hardware keyboard or VoiceOver activates a button without showing its [pressed style](../guide/07-shared-components.md#style-the-pressed-state). A touch shows it.
- `Image` loads `file://` URLs in the generated app; the backend crate also accepts `resource://` names from the app bundle. Neither loads web URLs.
- The generated app keeps your screen inside the safe area, below the status bar and above the home indicator. With the backend crate, `UIKitHost` reports the insets instead, and `pt-safe` and the other [safe-area utilities](../guide/07-shared-components.md#clear-the-status-bar-and-home-indicator) pad by them.

## Ship an update without the App Store

The App Store build carries the UIKit host, the interpreter, and a copy of your screens. To change the screens afterwards, publish a code push release for iOS:

```bash
leptoskit native bundle --target ios --out dist/ios
leptoskit codepush release --from dist/ios --platform ios --channel production
```

The app downloads the release when the user asks for an update, tries it, and keeps it only if it renders. Anything that needs new native code, such as a new plugin or permission, still needs an App Store release. [Code push](../guide/05-code-push.md) covers signing, publishing, and rollback, and [host projects](host-projects.md#code-push-in-the-generated-apps) the update flow inside the app.
