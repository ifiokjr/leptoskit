# Streams, pinned pages, an offline queue, and re-auth

The live connection now carries streams and long lists, keeps working through a dropped network, and follows sign-in without a reload.

- **Streams.** `#[rpc::stream]` declares an `async fn` that returns `impl Stream<Item = T>` (or `Item = rpc::Result<T>`), runs as the caller, and implements the new `rpc::StreamOperation`. The client opens it with `stream { stream, name, args, credits }`, grants more room with `credit { stream, n }`, and stops it with `cancel { stream }`. The server reads the next item only once it has a credit, so a slow client never makes it buffer more than it asked for. A stream ends with `end { stream, reason, err? }`: `done`, `failed` or `interrupted`. `#[rpc::stream(resumable)]` takes a `cursor` argument, its items implement `rpc::Resumable`, and the client opens it again from the last item's cursor after a reconnect. `rpc::use_stream(move || S { … })` shows one on screen. Streams work over the WebSocket and server-sent events, and `#[api]` publishes them as the new `Kind::Stream` and `ApiKind::Stream`, in `/asyncapi.json` and not in `/openapi.json`. Generated SDKs skip them for now.
- **Pinned pages.** A query that takes `rpc::PageArgs` and returns `rpc::Page<T>` implements `rpc::Paginated`, and `rpc::paginate(db, query, &page, order, key)` reads one page by a unique column. `rpc::use_live_paginated(move |page| Q { …, page }, size)` builds on `leptoskit_query`'s infinite queries, with `.load_more()` and `.has_more()`. Every loaded page is its own live subscription, and loading more pins the last page at its end, so an insert into page one lengthens it and leaves page two alone. A page's rows travel as a patch of its `items`.
- **The offline queue.** Mutations and actions dispatched while the live connection is down wait in order and go out when it comes back. `ClientConfig::offline_queue(true)` also keeps them on the device (`localStorage` in the browser, the store plugin in a native app), so they replay after a restart: mutations with their idempotency key, and actions only if they were never sent. `ClientConfig::offline_store` takes any `QueueStore`, such as a `MemoryQueue`. `rpc::use_live_status()` reports the connection's state and how many calls wait.
- **Re-authenticating an open connection.** `rpc::client::reauthenticate()` has the live connection read as the current credentials: a bearer token goes in an `auth` frame on the open connection, and a cookie session reconnects without resuming. `leptoskit_auth`'s client calls it on every sign-in, sign-out and token renewal, with its `rpc` feature on.
- **Read-your-writes from the ordinary hook.** `use_mutation(mutation_scope::<M>())` goes over the live connection while it is open, and resolves once its writes are on screen, as `use_live_mutation` does; otherwise it calls over HTTP.
- **A fix for keyed patches.** A row inserted before others in a keyed list now goes in at its place on the client, instead of replacing the row there.
- **Testing.** `rpc::testing::LiveClients` connects real `LiveClient`s to a `Live` in the same process, with headers to sign in by and an `outage` switch.
